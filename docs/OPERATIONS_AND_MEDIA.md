# 素材、预算与失败恢复操作说明

适用：2026-09-28 第二批及第三批部分改动。只完成代码和本地验证，未进行付费验收或公司正式部署。

## 素材通道

- 生产模板已有 Caddy 独立媒体域名、共享持久卷和独立媒体服务。`VIDEO_AGENT_MEDIA_BASE_URL` 指向固定 HTTPS 域名；`runtime.validate` 在生产模式拒绝 trycloudflare 临时域名。
- v4 的视频/音频参考在实际生成 Build 前，经 `media_preflight.verify` 原子发布。按内容哈希签名，有效期为当前时间桶后24至48小时。使用保存的本次运行配置，完整 GET 校验字节数和 SHA-256，拒绝重定向、HTML替代页、损坏/截断文件；失败发生在付费提交意图之前。
- 预检记录在工程 `production/media-preflight/`。只记录文件摘要、字节、到期和检查结果，不记录签名URL。Worker GET 成功仍不能证明供应商网络可读；真实供应商读取需另行验收。
- 管理员需负责固定域名、证书、磁盘和存储备份。开发临时隧道仍不由本地监督器托管；不要把本地临时域名当公司部署。
- `python -m scripts.cleanup_media` 默认只报告过期副本。至少保留7天；`--apply` 要求 Worker 心跳已停止、无活动任务及未知提交，才删除过期 `reference-blobs` 副本。它不会清理原始上传、任务工程、审查证据或成片。尚未实现完整任务数据生命周期和自动清理调度。

## 预算

- `plan_budget.costs` 对每段按当前能力最小4秒、整数向上取整计算首轮需求；上限15秒。不是把成片时长直接当生成成本。
- `ensure_plan_budget` 在事务中为同一账号预留整片尚未生成部分；`reserve_submission` 将本次预留转入实际提交账本。返修不得占用其他未完成片段的最低需求。
- 配额单位为生成秒数。历史失败、未知提交、已受理请求均保留在已预留账本中；不能自动当退款。全片预留有效期1小时，恢复时重新检查；跨日按当天账本与新预留核算。
- 原子预留使用 SQLite 写事务或 PostgreSQL 事务级 advisory lock。后者本轮未实测。
- 不调用供应商余额接口、不推算货币价格。模型理解、生图、TTS费用未计入这份视频秒数预算；准确货币预算仍待服务商计费接口支持。

## 已失败生成的新版本

`POST /api/jobs/{id}/retry-failed-generation`，JSON：`{"build_id":"原本地Build编号"}`。

网页对具备可靠供应商任务号的 v4 失败片段显示新版本按钮，并说明消耗新额度。后端：

1. 校验登录所有权、暂停状态、当前片段最新Build及不存在未知提交。
2. 用该Build保存的原运行配置，读取原供应商任务；当前只实现 AutoDL Wan。必须明确返回 FAILED/CANCELED/CANCELLED。
3. 在事务中重新核对状态、全片剩余额度、单段次数上限和单次测试授权，保存终态凭据和一次性版本授权。
4. 保留旧Build、原编号、失败证据和原费用预留。生成指令加入固定版本标识，形成明确的新请求；重复操作复用同一工程与提交日志，不通过改URL逃避去重。
5. 真正提交时消耗授权；回执丢失仍保持未知状态，不能再次生成。

普通“继续处理”仍不表示同意对失败生成创建收费新版。HTTP 500 即使含“余额不足”，仍不能认定未受理；错误原因与受理确定性分别保留。无可靠任务号的自动对账仍未实现。

## 全片配乐库

管理员可在 `VIDEO_AGENT_MUSIC_DIRECTORY` 下维护音频文件和 `catalog.json`：

```json
[
  {
    "id": "soft-demo",
    "file": "soft-demo.wav",
    "description": "轻快、无歌词，适合商品介绍",
    "approved_for_company_use": true,
    "license_note": "填写公司实际获得的使用许可记录",
    "allow_loop": true
  }
]
```

不要直接把示例当许可。只有管理员确认公司可用、许可说明非空、路径位于库内的条目才进入创作模型候选。

规划返回 `audio_plan`，三种模式：`original` 保留片段声音；`silent` 后期移除音轨；`library` 选择库内 `music_id` 和音量，合成一条贯穿全片的配乐，保留原对白和环境声。同一配乐不会每段重头播放。缺少素材、哈希变更、时长不足且不允许循环时，停止在本次视频提交前。

本地 FFmpeg 已验证有声音片段＋无声音片段＋统一音乐的混合、时长与原声保留。代码不会下载或自动生成配乐。库为空时保持原片声音路线。专用准确旁白/TTS、字幕后期、基于对白自动闪避音量、模型是否完全遵守“不单独生音乐”仍未完成/未真实验收。

## 跨场景身份

`depends_on` 继续绑定动作结束帧；新 `identity_depends_on` 绑定前面单元实际审片挑选的 `identity_frame`，附有 `identity_state`、文件哈希和验收版本。新场景只借用外观，不要求复制旧背景/动作。身份来源返修后，下游依赖也会失效。

这提供了无上传图时使用已验收视频建立身份基准的执行路线。是否正确识别共享角色仍依赖规划模型；复杂多角色注册、生成前统一角色图以及真实一致性质量仍待完善。不要声明文字多场景已经稳定一致。

## 本地监督与停止

新的启动记录保存监督进程及子进程的 PID、启动时间与命令。监督进程退出后，停止工具只给身份仍一致的子进程发送 SIGTERM，不对复用PID或不匹配的进程发信号。旧启动记录没有子进程身份时仍不会猜测清理。
