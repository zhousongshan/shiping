2. `app/media_preflight.py`：在实际Build前发布并完整GET本次签名视频/音频，检查哈希、长度、状态、重定向和有效期；失败发生在提交意图和付费Build之前，记录无签名URL。没有原始视频输入的文字/图片路线不调用此下载预检。

4. 错误分类：`insufficient account balance` 单独标记原因；若HTTP 500受理不明，仍保留SUBMISSION_UNCERTAIN。
5. 跨场景身份：规划增加独立身份依赖，审片保存可早于片尾的清晰身份帧，实际请求绑定帧和验收版本；与动作结束帧分开。身份基准修改使后续依赖失效。
6. `app/film_audio.py`：全片声音方案支持原声、后期静音、管理员许可配乐库。完整音轨保持原对白/环境声，音乐贯穿全片，不按镜头重启；本地FFmpeg实测两段（一段有声、一段无声）混合成功。尚无专用准确TTS/字幕路线。

## 第三轮：五组真实素材验收

本轮由用户新授权真实五组试做，不包含正式部署。完整事实见 [验收报告](ACCEPTANCE_2026-09-28_PIG.md)。首轮五组均在视频Build前暴露流程问题，经过有限代码修复保留原任务恢复；已修复项及真实结果分别记录，禁止混为“全项目稳定”。

实测把后续优先级调整为：

1. 商品固定外观与动作分开：对闭眼刺绣、服装、挂带等建立来源明确的不可变约束；规划新增商品结构须有依据，审片直接对照图片。
2. 参考策略落到执行与验收：借鉴场景/节奏时不强带原商品结构；要求参考同款主体时提取并绑定真实主体基准，不能只把视频转成几句文字后纯文生视频。
3. 时长适配保全首尾事件：解决13秒请求与12.1秒成片之间的差额，采用区间/允许的小幅变速须经过声音和关键事件复核；禁止默认从尾部删除内容。
4. 检查矛盾定位：采用片段与成片基于同一实际文件/时间区间核验；保留原始失败与检查异常，不能把模型分歧转成自动收费许可。
5. 完成上述修复后，再按新的有限预算复测失败组合、长视频与多人场景，记录首次交付率及管理员介入次数。当前单组样本不足以证明稳定性。

本轮验收已结束：三组完成、两组未通过，171项回归170通过1跳过。真实样片暴露的质量问题仍按上述优先级待修复；不是整个计划完成。
