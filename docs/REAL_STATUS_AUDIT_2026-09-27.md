## 关键复现与测试界限

1. 当前测试共运行 92 项：91 项通过、1 项 PostgreSQL 实测跳过，约 21.5 秒。大多数生成步骤使用模拟返回值；不等于真实成片验收。
2. 额外使用临时数据库，仅创建一条任务，在执行函数写入 `waiting_build` 后尚未返回时，调度器重复领取了同一任务：`dispatch_count=2`。未调用模型。根因是 worker 的运行中任务集合没有用于排除 claim，且 waiting_build 状态会在任务仍执行时提前写入。
3. 真实文件验证：本次两个版本均可解析、含视频和音轨；历史三个 completed 文件存在且可播放。三个 completed 都来自旧制作版本。本地当前 v2 的六条记录没有 completed。
4. 只读模型列表探测 HTTP 200、约 1.7 秒，仅证明探测当时可连接，不证明生成或长期网络可靠。
5. 手动候选拼接用隔离副本实测，不改动真实任务，也不产生新的视频生成费用。

## 阻止可靠交付的问题

优先修复同一任务重复执行及状态覆盖，再修复审片的证据与判定一致性、生成版本直接预览与单元版本选择，随后恢复参考素材通道，最后按输入组合和时长做真实端到端验收。上述缺陷本次作为审计发现记录，不能因为现有测试通过而标记解决。
