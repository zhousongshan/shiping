# 2026-09-28 小猪商品素材五组真实验收

## 范围与判定

用户提供一张粉色闭眼毛绒小猪图片，以及约12.096秒、864×496、带音轨的商品展示参考视频；明确授权五种输入各做一个，优先图片＋参考视频。使用当前项目正常HTTP上传/任务接口和Worker执行，未使用旧验收脚本或替代视频工具生成。

五组：无文字图片＋参考；仅文字；文字＋图片；文字＋参考；文字＋图片＋参考。无文字组保留自动时长/画幅，其他四组目标12秒横屏。每单元最多两次生成，未知回执不能重发。不涉及正式部署。

成功须同时满足：正确输入路径、完整时长与可播放下载、相应主体要求、动作/展示结构、参考采用策略、声音要求。纯文字组按文字外观验收，不要求像素级匹配未上传图片。程序完成不等于视觉合格；一组一个样例不能证明长期稳定。

## 已确认的实测问题与后续修复重点

1. **主体特征约束不足**：无文字图片＋参考组实际约3至6秒、11秒玩偶睁眼，9至10秒增加了蓝色挂带。参考视频的产品结构混进了新商品，不能仅凭“粉色小猪”就认定主体一致。需要把商品不可变外观（刺绣眼睛、服装、配件、肢体结构）与可动画动作分开，要求规划解释新增结构的来源，并用原图与实际片段独立核验。
2. **整数生成时长与成片时长衔接不正确**：此组目标12.1秒，接口生成13秒；`unit_review.py`固定从0裁至目标，原片约12.2秒的彩纸和收尾文字被截掉。应先规划整数请求的时间分配，保留完整动作；采用区间必须检查首尾关键事件，小幅变速仅在声音/动作允许且复查通过时采用，不能默认裁尾或普遍强制变速。
3. **审片证据互相冲突**：同一采用片段的单元检查曾声称存在剪刀手和彩纸，成片检查却发现缺失，画面抽帧也确认尾部差异。系统正确停在needs_review，但并没有解决质量问题。需要把实际帧/区间对应到要求，冲突时针对相同文件和时间密集复核；不要反复让模型读计划后重复结论，更不能把检查分歧直接当作收费重生成依据。
4. **参考借鉴边界仍需改进**：无文字默认adapt仍把挂带与品牌尾板带入计划；本轮调整了创作提示但未阻止这个实际输出。应在规划阶段核验“引用的内容”和“图片主体可支持的动作/结构”，默认只借鉴表达，不推导新商品功能。此项不能标为已解决。
5. **要求ID与单元ID混淆**：纯文字审片把u1写入requirement_ids，两次泛化纠错均失败。已补充允许编号与额外检查填[]的规则；在持有执行租约、禁止Build的单独检查进程中成功检查原视频，生成次数保持1次。得到有效fail后，按原任务最多两次的上限继续正常返修，不伪造通过。

6. **仅参考素材的同款主体缺少生成基准**：文字＋参考首版实际为绿色连体衣、普通蓝色帽子小猪，原参考是绿色带兜帽的毛绒外壳、蓝色波点尖睡帽，两者显然不是同款。检查生成凭据发现style路线images为空、没有原参考视频输入，只有文字描述。应在用户明确使用参考主体时从参考提取经确认的主体帧，作为身份素材绑定生成；参考的“借鉴方式”和“主体来源”必须分开表达。成片检查已拦下该首版，系统按原2次上限进入第二版，但只靠提示词重生成不能证明结构问题已修复。

7. **检查时间的毫秒舍入误判（已修复）**：第二版实际12.028005秒，审片疑点写为12.03秒，两次均误判越界。仅允许终点超出不多于0.005秒时归一到实际终点，更大越界、负起点、空区间、NaN仍拒绝；错误提示列出精确上限。已有视频复查后正常落到needs_revision，生成预留仍为24秒，没有第三次生成。

以上是本次样本中可复现的问题；不代表其他未测试场景都正常。后续应优先解决需求到画面的一致性，再扩大多人、长视频和公司部署验收。

- 本机 `data/acceptance/2026-09-28-pig/deliverables/` 保存5份带中文名称的视频；未通过者文件名明确标出“未通过”。原始版本、所有审查、回执和本轮中间错误仍在原任务工程中。
- 三份正式成片及两份候选的下载接口均实测200并与本地文件哈希一致；三份正式成片经过完整解码检查。网页实测文字＋图片任务显示完整视频1/1、视频预览和“下载成片”。无文字入口仍为选填。
- 画面核验使用实际抽帧及关键边界，声音内容引用项目的真实音频分析；未将“文件含音轨”等同于已人工听审或声音质量全部合格。3组“通过”指本次画面抽查、技术与系统声音检查，不代表用户最终创意满意度或长期稳定性。
- 样例都只有一个视频生成单元（叙事小节可有多个）；此次不能验证长视频多单元接缝、人物、复杂多角色、并发公司环境与正式部署。
